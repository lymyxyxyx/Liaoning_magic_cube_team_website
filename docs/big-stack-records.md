## 首次上线

先应用数据库迁移：

```bash
npm run db:migrate
```

仓库内的权威基线是 `data/big-stack-baseline.json`，共 805 人，其中刘奕辰只保留 64。首次替换现有大堆数据有两种方式：

1. 登录周赛管理员账号后打开 `/weekly/big-stack?event=333`，选择“全量基线替换”，上传修正版 `.xlsx`，先预览再确认导入。
2. 在已配置 `DATABASE_URL` 的服务器执行：

```bash
npm run big-stack:baseline
```

两种方式都只替换三阶大堆榜，不影响二阶、金字塔、枫叶和镜面榜；操作在一个事务内完成，失败时会整体回滚。命令行导入固定校验 805 条唯一姓名和“刘奕辰 = 64”。

## 日常维护

后台默认使用“PB 合并”模式：

- 新选手会新增；
- 更高成绩会覆盖当前 PB，并留下历史；
- 相同或较低成绩会忽略；
- 缺席 Excel 的选手不会被删除；
- 优先按周赛选手 ID、WCA ID、唯一的完全同名匹配；
- 不做模糊匹配，未匹配或歧义记录交给管理员处理。

Excel 至少需要“姓名”和“最高记录”两列，也可以增加“周赛选手ID”“WCA ID”“达成日期”“备注”。后台还支持单条新增、修改、删除、搜索和最近修改历史。降低成绩、修改身份或删除时必须填写原因。

## 2026-10-09 后续加固

- 项目切换重建榜单与操作状态，避免二阶显示三阶数据和跨项目沿用导入预览。
- 游客接口及页面数据只包含公开展示字段，移除备注、内部绑定 ID 和编辑版本。管理员可读取完整字段；旧页面需刷新后编辑。
- 修改、删除强制携带原始数据库时间戳版本；版本缺失返回 428，已变更返回 409。页面刷新列表，保存冲突时保留未提交的编辑内容，取消并重新打开最新记录后再操作。
- ID/WCA ID 冲突或同名已绑定另一位选手时阻止自动导入。未知明确 ID 必须更正或清空。正常未绑定记录仍允许保留；494 条未绑定基线不自动重绑。
- 空成绩与不真实的日期会报错，明确的零成绩有效；手工、合并和基线均限制整数数量 0..10000，并检查姓名、WCA ID 和备注。
- 全量替换前把每条旧记录完整保存到修订表，action 为 baseline_removed，关联当前 import_batch_id。可按批次提取 before_record 恢复；目前没有一键恢复界面，恢复仍需核对身份唯一性与替换后的修改。
- 后台导入提交必须提供最新预览 token。token 覆盖行数据、项目、模式、选手档案与当前榜单；任一变化要求重新预览。API 提交仍会重新校验。
- 大堆写入统一先取得表锁，保护未绑定记录查重以及导入与单条操作；按照当前周赛规模串行写入，读取仍可进行。相同姓名的真实不同身份不采用全局姓名唯一约束；补绑定请编辑已有未绑定记录，不要新增重复记录。
- Excel 压缩文件上限 8MB、单项解压 16MB、总解压 32MB、最多 10000 行，限制内部文件和工作表数量。超过限制需拆分后使用 PB 合并。
- 历史界面改为“刷新 PB”，不再表示已到账积分。points_awarded 保留历史兼容，不涉及真实积分台账。

命令行基线替换也会保留旧榜快照并检查姓名及数量。但 `/app/data` 仍是持久卷，执行前必须确认服务器基线 JSON 与仓库一致。日常更新优先后台 Excel 预览与 PB 合并；本次修复不重新导入现有基线。

隔离集成验证：`node scripts/verify-big-stack-integrity.cjs`。需要 DATABASE_URL，创建并删除独立 schema，验证竞争编辑、过期删除、重复新增、身份冲突、预览版本、PB 合并和替换快照，不读写线上榜单。
