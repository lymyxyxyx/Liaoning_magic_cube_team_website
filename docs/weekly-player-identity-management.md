# 周赛编号与 WCA ID 管理（2026-10-10）

入口：登录周赛管理员后，打开 `/admin/weekly/players`，默认页签为“周赛编号 / WCA ID”。支持编号、姓名、拼音和 WCA ID 搜索，编辑编号、绑定 ID、确认状态与修改原因。

大堆与普通周赛共用同一个选手库和周赛编号，不单独创建大堆编号。大堆管理员可按“原周赛编号＋姓名”关联记录，后台表格展示共用编号；未关联历史记录显示“未关联”，需核对后选择现有选手。

周赛编号是每位选手的固定号码，独立于内部 player_id、成绩名次和每周赛事。迁移先保留长期卡原登记顺序生成的旧编号，再给其他 v2 选手分配号码。新选手通过数据库触发器自动领取下一号码；编号必须为 1..999999，启用和停用选手均占用编号。号码修改不改变成绩，公开榜单继续不显示号码。

编辑入口提供“从辽宁魔友库匹配 WCA ID”，沿用已有辽宁可见档案的姓名、城市和性别匹配规则，展示候选后人工确认；不因同名自动绑定。

WCA ID 可改正或清空，需符合 2019ABCD01 格式且不能重复绑定。修改输入会取消已确认状态，管理员核对后再勾选确认。普通周赛游客成绩只展示已确认 WCA ID。操作保留选手的内部 ID，因此已有成绩与 PB 不迁移、不重新匹配。

保存使用原始时间戳版本，过期页面返回 409、缺失版本返回 428。编号或 WCA ID 冲突不会部分保存。保存同步关联长期卡的 WCA 字段，更新/取消匹配候选确认关系，并更新已绑定大堆纪录的 WCA ID（不改数量、姓名、名次），保存大堆修订快照和身份修改记录。大堆中另一个人或未绑定纪录使用目标 WCA ID 时阻止修改，需先核对原纪录，不自动按姓名合并。

其他资料编辑不再覆盖已有选手的 WCA 绑定；候选确认也调用同一身份事务。选手导入回滚只恢复其实际修改的性别和生日，并保留后来维护的身份字段。已有大堆纪录或身份维护记录的导入新增选手，回滚时停用保留，不删除档案。

迁移：`202610090002_weekly_player_numbers.sql`。本次需要完整备份、数据库迁移和整包部署；不可仅做 code-only 发布。数据库为 v2 WCA ID 和周赛号码增加唯一索引，重复数据需先处理，不能静默改绑。

验证：`node scripts/verify-weekly-player-identity.cjs`。使用独立 schema 验证旧编号保留、新号自动分配、重复约束、过期版本、WCA 同步、旧资料保存保护及并发修改，不读写线上档案。

大堆更新仍在 `/weekly/big-stack?event=333`：日常用 Excel“PB 合并”，仅更高数量刷新当前纪录；单条编辑允许填写原因纠错、降低或删除。全量基线替换用于确实需要替换整榜时，须预览和确认，替换前保留快照。普通周赛的大堆成绩录入与独立长期大堆榜是两个数据流程，不会自动互相导入。
