# 大堆长期 PB 系统复查（2026-10-09）

范围：最新提交 42997c6 的页面、公开接口、身份匹配、Excel 解析、PB 合并、全量替换、单条修改删除、数据库约束及历史记录。没有修改线上成绩或管理员账号，没有部署代码。

## 优先修复

### P1：切换项目后，标题与榜单数据不一致

位置：`app/weekly/big-stack/big-stack-console.tsx:40`、`app/weekly/big-stack/page.tsx:33`。

线上 Chrome 实测：进入三阶显示 805 人；点击二阶后 URL 与标题更新，仍显示 805 人；刷新二阶页面才显示 0 人。客户端只用 initialRecords 初始化 useState，项目变化后没有更新状态，组件也没有按 eventId 重建。

除了榜单，编辑对象、文件、导入预览等状态也会继续保留。后台可能拿着上一项目的预览提交当前项目，故需同时清空操作状态。建议按项目重建组件，或显式协调所有状态；确认导入还要校验预览项目、模式与文件。

### P1：明确不同的选手 ID 仍会按同名合并

位置：`lib/big-stack.ts:470`、`lib/big-stack.ts:224`。

用公开服务函数和只读模拟数据复现：榜单已有选手 A（同名、100）；导入另一位同名选手 B（独立 playerId 和 WCA ID、120）。预览无错误，判为 improved，existingRecordId 指向 A，resolvedPlayerId 指向 B。提交分支会把 A 的纪录和绑定改成 B，丢失 A 的当前 PB。

原因：强身份未命中后，无条件退回唯一同名匹配，未检查该同名记录是否已绑定另一个人。建议遇到明确不同身份时禁止姓名回退；只能在安全的未绑定候选上进行补绑定，否则要求人工解决。

### P2：Excel 的空成绩变成 0，且基线绕过数量上限

位置：`lib/big-stack-xlsx.ts:59`、`lib/big-stack.ts:178`、`lib/big-stack.ts:605`。

本地构造工作簿实测：姓名存在、成绩列为空，解析为 count=0，errors=[]；10001 也能通过预览。空字符串被 Number 转成 0。手工与合并新增限制 0..10000，而全量基线直接批量 INSERT，绕过 requiredCount，因此不同录入方式规则不一致。

建议统一校验空值、整数范围、姓名长度和真实日期，在预览阶段逐行报错，提交时再次校验，防止全量替换把漏填成绩写成零。

### P2：修改和删除没有过期版本保护

位置：`lib/big-stack.ts:310`、`lib/big-stack.ts:344`、`app/api/big-stack/[id]/route.ts`。

行锁只保证写入顺序。两个管理员基于同一个旧记录操作时，后一次保存仍会使用旧字段覆盖新修改；删除也可能删除别人刚刷新的 PB。updatedAt 随记录返回，但接口未强制对比客户端版本。

建议采用原始 PostgreSQL 时间戳版本，修改与删除强制 expectedVersion，冲突返回 409；保留未保存输入并刷新榜单。账号体系不需要改变。

### P2：公开接口和页面序列化包含内部备注与绑定 ID

位置：`app/api/big-stack/route.ts:30`、`app/weekly/big-stack/page.tsx:33`。

匿名线上接口实测包含 playerId、note、updatedAt、sourceLabel 等完整字段。当前 805 条备注为空，因此没有确认现存敏感备注泄露；但以后管理员填写的内部备注会直接公开。只隐藏表格列不能解决，服务端传给客户端组件的属性也必须裁剪。

建议公开 DTO 只保留排名与展示所需字段，管理员响应另加备注、内部 ID、编辑版本。

## 其他需要补齐的保护

- **身份冲突缺少校验**（`lib/big-stack.ts:444`）：本地复现 playerId 指向 A、WCA ID 指向 B，预览无错误无提醒，直接使用 A 档案中的 WCA ID。未知 playerId 也只给警告并继续按未绑定处理。应对明确冲突阻止提交；正常未绑定记录继续允许保留。
- **未绑定记录的重复保护不足**（`lib/big-stack.ts:495`、迁移 `202610090001_big_stack_long_term_pb.sql:10`）：单条新增携带 ID 时不查同名未绑定记录，可能把已有长期 PB 新增成第二条。纯未绑定姓名查重没有并发锁或数据库约束，两次并发新增也可能都通过。应提供补绑定流程并协调查重与写入；不能简单以全局姓名唯一约束合并真实同名选手。
- **全量替换缺少可恢复的旧榜快照**（`lib/big-stack.ts:178`、`scripts/import-big-stack-baseline.mjs:56`）：事务保护失败回滚，但成功后日志只记录新榜，没有完整保存被删除的榜单；批次 summary 不能恢复原榜。应保存旧榜批次快照，并校验提交仍对应已审阅的文件、项目及榜单版本。
- **Excel 解压没有总量限制**（`lib/big-stack-xlsx.ts:79`）：8MB 限制针对压缩文件，所有工作表及共享字符串均解压到内存，没有单项、总解压大小、工作表数和行数上限。导入需要管理员认证，属于受限入口的资源风险。建议在读取 file.arrayBuffer 前检查 file.size，解压时持续计数并及时关闭 ZIP/流。
- **积分文案缺少真实台账支撑**（`app/weekly/big-stack/big-stack-console.tsx:205`）：points_awarded 只存入大堆修订日志，没有真实积分账户更新；“PB积分 +1”容易误导。应改成审计标识，或在正式定义积分规则后接入台账。
